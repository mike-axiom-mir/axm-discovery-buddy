# AXM Discovery Buddy

[![Apache License 2.0](https://img.shields.io/badge/license-Apache--2.0-3b82f6)](LICENSE) ![Status experimental](https://img.shields.io/badge/status-experimental-f59e0b) ![Local first](https://img.shields.io/badge/local--first-direction-16a085)

AXM Discovery Buddy is a local-first repository and workspace discovery tool for large project collections. The current tree contains the first materialized scanner: dependency-free Python that finds local Git repositories, reads bounded evidence surfaces, builds a deterministic machine-readable index, and renders a human-readable map without uploading workspace contents.

## First run

Python 3.11+ is enough; the scanner has no runtime package dependency.

```bash
python -m discovery_buddy scan /path/to/workspace --output-dir /tmp/axm-discovery
```

This writes:

- `/tmp/axm-discovery/local-discovery.json`
- `/tmp/axm-discovery/local-discovery.md`

Rebuild the expected outputs in memory and fail if the saved map has drifted:

```bash
python -m discovery_buddy verify /path/to/workspace --output-dir /tmp/axm-discovery
```

## What it discovers now

For each local Git repository inside the bounded scan depth, the scanner can report:

- workspace-relative repository path, current branch, and Git head;
- SHA-256 presence evidence for `README.md` and `AGENTS.md` without copying their contents into the index;
- `.axm/beacon.json` protocol, declared interests, and publish tags;
- declared capabilities from `registry/*capabilit*.jsonl`, including the `registry/capabilities.jsonl` shape already generated by AXM Collaboration Platform;
- one deterministic content SHA-256 covering the normalized scan policy and discovered records.

The cross-repository bridge is static evidence consumption. Discovery Buddy does not import, execute, install, or make another AXM repository a runtime dependency.

## Privacy and public-export boundary

Default output is `LOCAL_ONLY`.

- The absolute scan root is never written into the index.
- Arbitrary source-file contents are not exported.
- Git directory pointers are followed only when their resolved target remains inside the selected scan root.
- Common generated/dependency directories such as `.git`, `node_modules`, virtual environments, `dist`, and `build` are excluded from traversal.

Public mode is deliberately fail-closed:

```bash
python -m discovery_buddy scan /path/to/workspace --output-dir /tmp/axm-discovery --public
```

A repository is omitted unless it carries an explicit `.axm/discovery-public.json` marker using schema `axm.discovery-public/v1` with `public: true`. Public output strips local workspace paths and Git work-state fields and keeps only bounded whitelisted discovery metadata.

That marker is export intent, not proof of licensing, release readiness, runtime correctness, safety, or CANON status.

## Current truth

**EXPERIMENTAL / MATERIALIZED v0.1 SCANNER**

Implemented and locally regression-tested in this tree:

- deterministic bounded repository discovery;
- Git branch/head discovery without requiring a Git subprocess;
- beacon metadata adapter;
- capability-registry adapter;
- deterministic JSON + Markdown index generation;
- exact-byte stale-map verification;
- explicit local/private versus public-safe output boundary.

Still not implemented or claimed:

- automatic GitHub-wide synchronization;
- live filesystem watching;
- resumable million-file scan checkpoints;
- pull-request or remote-branch status ingestion;
- semantic source-code analysis;
- measured large-workspace performance or scale guarantees.

A declared capability is discovery evidence, not runtime proof, quality, authority, or CANON. The existing Organ Beacon remains a separate proposal-only evidence transport lane.

## Verification

